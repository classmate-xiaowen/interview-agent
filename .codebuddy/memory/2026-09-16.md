## 故障修复：chat/session 返回 500
- 链路：`POST /api/chat/session` → `InterviewSession.start()` → `llm.chat_structured` → DeepSeek。
- 原因1：模型名 `v4flash` 非 DeepSeek 合法 ID，DeepSeek 报错 `invalid_request_error: supported names are deepseek-flash, deepseek-v4-pro`。已改为 `deepseek-flash`（用户所说的「v4flash」即 flash 版）。
- 原因2：DeepSeek 默认开启 thinking 模式，不支持 instructor 默认的 `tool_choice`（函数调用）结构化输出，报 `Thinking mode does not support this tool_choice`。已把 `app/services/llm.py` 的 instructor client 改为 `mode=instructor.Mode.JSON`（response_format=json_object），不依赖 tool_choice。
- 注意：`mode` 必须设在 `instructor.from_openai(..., mode=...)` 上，不能传进 `.create()`（会 multiple values for 'mode' 报错）。
- 验证：探测脚本 + 运行中的服务 `POST /api/chat/session` 均返回 200 并正常出首题。`.env` 已同步 CHAT_MODEL/GUARDRAIL_MODEL=`deepseek-flash`；config.py 与 .env.example 同步。
- 提示：uvicorn `--reload` 会在改 .py 时自动重载并重新读取 .env；若仍异常让用户 Ctrl+C 重启。未做 git commit。

## 故障修复：前端 /api/* 全部 500（Vite 代理 IPv6 不匹配）
- 现象：浏览器 `/api/profile` 等返回 500，但后端 `127.0.0.1:8000/api/profile` 直接访问 200 正常，`/health` 也 200。
- 根因：`vite.config.ts` 代理目标写 `http://localhost:8000`；Windows 上 `localhost` 优先解析为 IPv6 `::1`，而 uvicorn 默认只监听 IPv4 `127.0.0.1`，代理连 `::1:8000` 被拒 → Vite 返回 500。
- 修复：代理目标改为 `http://127.0.0.1:8000`（强制 IPv4）。**注意：Vite 配置改动需重启 `npm run dev` 才生效**（config 不热加载）。
- 验证：直接打 8000 端口已确认后端健康；前端 dev server 重启后应正常。未做 git commit。

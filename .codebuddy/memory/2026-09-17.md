# 2026-09-17

## 面经市场/薪资动态适配功能设计（speak-agent）

用户目标：面试模拟时结合「候选人目标薪资 + 市场行情」动态调整出题难度、方向、公司侧重（动 interview_harness）。

### 已确认决策
- 数据落地：**结构化薪资字段（下限+上限，万元/年）+ market_tier 枚举** 为主，复用现有 `market_context` 自由文本补充行情。
- 难度策略：**薪资定基准难度 + 会话内按评分动态微调**（>=75 升级换方向 / <50 降级补基础 / 中间追问）。

### 已实现（Phase C）
- `backend/app/services/adaptation.py`：3 个确定性纯函数
  - `salary_to_baseline(lower, upper, tier)` → 1-5
  - `next_difficulty(cur, score)` → (新难度, 趋势)
  - `direction_hint(...)` → 注入 prompt 的方向提示
- `backend/tests/test_adaptation.py`：11 用例全过。

### 阈值校准（2026 实测行情，已联网核查）
依据：CSDN 2026 程序员薪资手册（初级10-20/中级20-40/高级40-70/专家50-200w）、小林coding 2026 校招开奖（大厂31.5-79w，多数起步31-40w）、脉脉2026（结构性回暖/AI暴涨/传统降温）。
- 难度分档（总包 w/年）：<15→1, 15-28→2, 28-45→3, 45-70→4, >70→5（专家门槛从 50w 提到 70w）。
- 档位偏置：大厂+1、外企/中厂/不限 0、创业-1。原因：大厂/外企总包虚高，同薪资对应更低经验层级，避免把数字顶到专家。
- 关键修正：大厂+25-30w 由4降为3，大厂+40-45w 由5降为4，外企+60-80w 由5降为4。

### 难度档位最终标定（2026-09-17 最新）
- 用户最终要求：薪资档位区间 **7k 起步 ~ 35k 封顶（千/月）**，之前 12.5-58k 的档位对其太高。
- 改为月薪直标 1-5：<12k→1, 12-18k→2, 18-25k→3, 25-30k→4, ≥30k→5。
- **恢复 DIFFICULTY_SCALE=0.65**（用户要求 7-35k 直标后再整体压一档）：分档结果 ×0.65 四舍五入。
  最终映射（千/月→难度，不限档）：<12k→1, 12-18k→1, 18-25k→2, 25-30k→3, ≥30k→3（35k 封顶落 3）。
  大厂+1（上限4），创业-1（下限1）；越界封底 1 / 封顶 5。
- tier 偏置不变：大厂+1、创业-1、外企/中厂/不限 0；低于/高于区间分别封底 1/封顶 5。
- `_to_annual_w`（×1.2）仅用于 direction_hint 展示「≈万/年」。

### 薪资单位确认（2026-09-17 后续）
- 用户确认薪资字段单位为 **千/月（月薪 k）**，如 25 = 25k/月 ≈ 30w/年。
- `adaptation.py` 入口统一换算 千/月→万元/年（×1.2，12 薪近似），分档阈值 15/28/45/70 仍以万元/年为基准（已用 2026 行情校准），不随单位失效。
- `direction_hint` 同步展示「k/月 ≈ 万/年」。

### 难度再调整（2026-09-17 后续）
- 用户要求「每个档位再降 35%」：`salary_to_baseline` 中对薪资分档结果先 ×DIFFICULTY_SCALE(0.65) 四舍五入，再叠加档位偏置。
- 最终映射（不限档）：<15w→1, 15-28w→1, 28-45w→2, 45-70w→3, >70w→3；大厂+1、创业-1。
- next_difficulty 与 direction_hint 逻辑不变。系数常量化便于微调。

## adaptation.py 新增角色维度（ROLE_PAY_OFFSET）
- 已为 `salary_to_baseline` 加 `role` 参数（默认 "后端"），并让 `direction_hint` 把 role 传入。
- `ROLE_PAY_OFFSET`（千/月，以"后端"为参考 0）：算法/AI/大模型 -8、数据 -4、后端 0、前端 +1、客户端 +2、运维/SRE +3、测试/QA +6。
- 逻辑：`eff_mid = mid + ROLE_PAY_OFFSET` 再走 `_band` 分档 ×0.65 → 档位偏置 → clamp。
- 偏移值来源：CSDN MCP 社区 2026 年报分岗位薪资中心差估算（v1，可调）。高薪岗同薪=更初级（负偏移），低薪岗同薪=更资深（正偏移）。
- 单测 16 个全过（含 5 个角色偏移用例：算法<后端<测试 排序等）。
- 已知限制：`×0.65` 封顶使 30k+ 高薪段角色差异被压到同一档(3)；v1 接受。

## 中国市场 MCP / 薪资数据源调研结论
- 面向中国市场的招聘 MCP 主要是**求职自动化爬虫**（Boss直聘 MCP 多个实现：dengshu2 / moon7z / mucsbr / Snseam），不是干净薪资 API。
- 真正带「薪酬查询 + 人才需求」的是 **handaas-recruitment-mcp-server**（招聘大数据服务）。
- 国内招聘平台（Boss/猎聘/拉勾）**无官方薪资 API**，MCP 靠 Playwright 爬，脆弱+合规灰，不宜作运行时校准源。
- 更靠谱的中国校准源：脉脉/猎聘/科锐/智联 年度报告 + CSDN 等社区整理的分岗位薪资（实测：普通开发初级10-20万、中级20-40万、高级40-70万；算法/大模型更高）。
- **设计原则已定**：adaptation.py 难度映射保持确定性纯函数，绝不委托给 MCP/LLM（防漂移、可测）；MCP 至多作离线/定时补充校验，不当运行时依赖。

## 修复：ChatPage 流式渲染出 raw JSON 的 bug
- 根因：`interview_harness.py` 的 `_system()` 系统提示写死"严格按 JSON Schema 回复，必须包含 references"，却被复用到流式出题/总结的 `llm.stream_text()`（原生 OpenAI 纯文本流式，不强制 JSON）。模型于是把 `{"question":"...","references":[]}` 当普通文本逐 token 吐出，前端原样渲染。
- 修复：`_system(json_mode: bool = False)` 仅 JSON 模式追加 JSON 指令；EVAL 结构化调用用 `json_mode=True`，首题/新题/总结的 `stream_text` 用默认纯文本提示（"不要输出 JSON"）。
- 关键点：最终 `InterviewTurn.references` 由 `_retrieve()` 向量检索独立生成，与模型 JSON 输出无关，拆分 prompt 不影响引用功能。
- 现状：references 常为空，是知识库无匹配片段的检索命中问题，与本次 JSON 渲染 bug 无关。

## 修复：新建对话一次性抛出多个问题
- 现象：每次新建会话（kickoff）AI 一次性问好几个问题；用户期望一个问题一个问题提问。
- 根因：非前端重复触发（前端只发一次 kickoff）。模型在 `stream_text` 出题时贪心，把"提出第一道问题"理解成可以罗列多题。
- 修复：`interview_harness.py` 三处提示词加强约束 —— ①`_system()` 纯文本分支追加"每轮只提【一个】问题，等回答后再继续，绝不一次罗列多个问题"；②kickoff 用户提示"只输出【一个】问题本身，不要附带多个问题或候选清单"；③下一题用户提示"同样只输出【一个】问题本身"。
- follow_up 路径用的是 `InterviewTurn.followup_question` 单字符串 schema，天然单题，无需改。

## 新增：国内化「分级评分校准」层（解决评分过苛 + 回答简短被压分）
- 痛点：原 LLM 用固定高标评分，且因面试回答简短而压分，整体过苛。
- 调研（国内化 skills）：①掘金《AI模拟面试官 Prompt 模板》作通用兜底 persona+流程纪律（一次一问/必追问）；②脉脉《大厂面试真正打分的5维度》(问题拆解/技术深度/编码质量/沟通协作/心智匹配)；③xtechtools《中国大厂技术面试2026全攻略》合格线+厂风权重（字节重算法、阿里重深挖沟通、腾讯重工程、美团重业务；八股文只背不讲取舍才扣分）。
- 实现：
  - `backend/app/services/adaptation.py` 新增评分校准层（确定性、可单测）：`difficulty_from_years(years)->1-5`；`SCORE_BAND[diff]=(floor,ceil,gate)`（国内合格线，级别越高达标分越低：1≈78-90/2≈72-85/3≈65-80/4≈58-72/5≈52-65）；`score_calibration(diff,company)` 生成中文校准句（简短不扣分+厂风权重）；`calibrate_score(raw,diff)` 软拉到区间+clamp（低于 gate 设30下限不强行拉入合格区，防漂移）；`score_to_level(raw,diff)` 由校准分确定性推导国内5级（优秀/良好/合格/待提升/不合格）。
  - `interview_harness.py`：import adaptation；`__init__` 加 `self.diff=adaptation.difficulty_from_years(profile.years)`；EVAL 提示注入"国内大厂5维+score_calibration"；EVAL 返回后 `evaluation.score=calibrate_score(...)`、`evaluation.overall_level=score_to_level(...)`、`self.diff=next_difficulty(...)[0]` 动态演进。
  - `schemas/interview.py`：`Evaluation.overall_level: Literal[5级]|None=None`。
  - 前端 `types.ts` 加 `overall_level`；`ChatPage.tsx` 的 `eval-tag` 优先显示 `overall_level`（复用现有色档，无新 CSS）。
- 验证：新增 `tests/test_adaptation.py`（7 用例：难度映射/区间单调/软拉入带/低分保留/层级映射/厂风权重）全过；schema+adaptation 共 13 用例绿；前端 `tsc --noEmit` 无错。
- 难度档默认来源：`profile.years`（harness 已持有 profile，无需新 UI）。

# 2026-09-18

## adaptation.py 新增角色维度（ROLE_PAY_OFFSET）
- 已为 `salary_to_baseline` 加 `role` 参数（默认 "后端"），并让 `direction_hint` 把 role 传入。
- `ROLE_PAY_OFFSET`（千/月，以"后端"为参考 0）：算法/AI/大模型 -8、数据 -4、后端 0、前端 +1、客户端 +2、运维/SRE +3、测试/QA +6。
- 逻辑：`eff_mid = mid + ROLE_PAY_OFFSET` 再走 `_band` 分档 ×0.65 → 档位偏置 → clamp。
- 偏移值来源：CSDN MCP 社区 2026 年报分岗位薪资中心差估算（v1，可调）。高薪岗同薪=更初级（负偏移），低薪岗同薪=更资深（正偏移）。
- 单测 16 个全过（含 5 个角色偏移用例：算法<后端<测试 排序等）。
- 已知限制：`×0.65` 封顶使 30k+ 高薪段角色差异被压到同一档(3)；v1 接受。

## 中国市场 MCP / 薪资数据源调研结论
- 面向中国市场的招聘 MCP 主要是**求职自动化爬虫**（Boss直聘 MCP 多个实现：dengshu2 / moon7z / mucsbr / Snseam），不是干净薪资 API。
- 真正带「薪酬查询 + 人才需求」的是 **handaas-recruitment-mcp-server**（招聘大数据服务）。
- 国内招聘平台（Boss/猎聘/拉勾）**无官方薪资 API**，MCP 靠 Playwright 爬，脆弱+合规灰，不宜作运行时校准源。
- 更靠谱的中国校准源：脉脉/猎聘/科锐/智联 年度报告 + CSDN 等社区整理的分岗位薪资（实测：普通开发初级10-20万、中级20-40万、高级40-70万；算法/大模型更高）。
- **设计原则已定**：adaptation.py 难度映射保持确定性纯函数，绝不委托给 MCP/LLM（防漂移、可测）；MCP 至多作离线/定时补充校验，不当运行时依赖。

## 修复：ChatPage 流式渲染出 raw JSON 的 bug
- 根因：`interview_harness.py` 的 `_system()` 系统提示写死"严格按 JSON Schema 回复，必须包含 references"，却被复用到流式出题/总结的 `llm.stream_text()`（原生 OpenAI 纯文本流式，不强制 JSON）。模型于是把 `{"question":"...","references":[]}` 当普通文本逐 token 吐出，前端原样渲染。
- 修复：`_system(json_mode: bool = False)` 仅 JSON 模式追加 JSON 指令；EVAL 结构化调用用 `json_mode=True`，首题/新题/总结的 `stream_text` 用默认纯文本提示（"不要输出 JSON"）。
- 关键点：最终 `InterviewTurn.references` 由 `_retrieve()` 向量检索独立生成，与模型 JSON 输出无关，拆分 prompt 不影响引用功能。
- 现状：references 常为空，是知识库无匹配片段的检索命中问题，与本次 JSON 渲染 bug 无关。

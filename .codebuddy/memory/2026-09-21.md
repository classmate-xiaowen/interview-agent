## 实现：模块 B + C（golden 样例集 + 回放引擎 + 基线漂移比对）
- 完成：把"点评质量"变成可回归的工程对象。
- 新增文件：
  1. `backend/eval/golden.jsonl`：12 条 golden 样例，覆盖难度档 1–5（注意 `difficulty_from_years(1)` 实际返回 2 而非 1！）、风格(pressure/gentle/deep)、公司、优/差回答。`raw_score`=fake 模式喂给校准层的"模型原始分"；`expected` 由 `adaptation.calibrate_score/score_to_level` 按难度档精确推算（含 `score==ceil`→"优秀" 的边界）。
  2. `backend/scripts/__init__.py` + `backend/scripts/replay.py`：回放引擎。`--mode fake`（默认，零 token）用确定性 fake LLM 跑完整 `stream_answer` 流水线（输入护栏→EVAL→校准→难度演进→输出护栏→trace 落库），只替换 LLM 原始分，校准/护栏走真实代码；`--mode live`（需 OPENAI_API_KEY）跑真模型端到端。`--update-baseline` 写 `eval/baseline.json`；默认与基线比，分数漂移 >5 分告警（防漂移，NFR-7）。报告写 `eval/eval_report.json`。
  3. `backend/tests/test_eval_replay.py`：3 个 pytest（覆盖全部条目 / 全通过 / NFR-7 引用必填且可解析），作为校准层与点评链路的 CI 闸门。
- 验证：`python -m scripts.replay --mode fake` → 12/12 passed, 0 drift（首次运行自动建 baseline）；`pytest tests/test_eval_replay.py` → 3 passed（耗时 ~86s，因每条跑完整异步流水线并落 trace，可接受）。
- 易错点记录：`difficulty_from_years` 边界——years<3 返回 2（非入门 1）；`score_to_level` 中 `score>=ceil` 判"优秀"。
- 下一步（尚未做）：模块 D 的 `GET /api/admin/eval/stats` 成本聚合（读 TurnTrace 按风格/题型聚合 token）；Prompt Caching（llm.py 无 cache_control）；live 模式需真实 key 方可跑端到端质量回归。

## 简历脱敏页增加「上传文件」入口（仅 TXT/MD，前端解析）
- 用户希望简历脱敏支持上传文件解析。决策：**前端本地解析**，仅支持 `.txt`/`.md`/`.text`（零依赖，用浏览器 `file.text()`），原文不离开本机，契合 FR「原文仅本地保留」。PDF/Word 暂不支持，选错格式 `message.warning` 提示。
- 改动仅 `frontend/src/pages/ResumePage.tsx`：引入 antd `Upload` + `UploadOutlined`；新增 `handleFile(file)`（`beforeUpload` 返回 false 阻止实际上传，读取后填 `original` 并清空 items/masked）；步骤①新增「上传简历文件」按钮（`accept=".txt,.md,.text"`）。后端无需改动——解析出的文本复用现有 detect/mask 流程。
- 注：PDF/DOCX 若以后要支持，需引 `pdfjs-dist`/`mammoth` 前端解析（仍保持本地）。

## RAG 改为真正使用 OpenAI 向量（修掉「embed 结果被丢弃」隐患）
- 用户选定方案2：真正用 OpenAI 向量，而非 Chroma 默认 MiniLM。
- 背景隐患：`knowledge_service._index` 调了 `embedder.embed(chunks)` 但没把向量传给 `store.add_chunks`（只传了 documents 文本），导致入库用 Chroma 默认模型（MiniLM 384维），而 `embed_model=text-embedding-3-small` 是 1536 维——存查两边虽都用默认模型能召回，但配置里的 OpenAI 模型从未生效、且白调 embedding 接口。
- 改动：
  - `backend/app/rag/store.py` 重写：① `add_chunks` 改为接收并写入 `embeddings`；② `query_chunks` 用 `embedder.embed([text])` 得到 query 向量后传 `query_embeddings`（不再用 `query_texts`）；③ 集合改为**懒加载** `_get_collection()`，首次使用时计算当前模型维度，若已有数据维度不符（旧 MiniLM 残留）则 `delete_collection`+重建，避免 HNSW 索引维度冲突报错；④ `delete_chunks_by_record` 也走 `_get_collection`。
  - `backend/app/services/knowledge_service.py`：`_index` 把 `embedder.embed` 返回的 `vecs` 随每个分块以 `embedding` 字段一起传给 `add_chunks`（不再丢弃）。
- 注意：`embedder.embed` 需有效 `embed_api_key`（默认 OpenAI）。首次访问集合会发一次 `__dim_check__` 探测 embedding（仅一次）。harness 调用 `store.query_chunks(text,...)` 接口签名不变。
- Lints 报告均为项目既有 basedpyright 噪声；`py_compile` 通过。未提交（按规范不自动 commit）。
